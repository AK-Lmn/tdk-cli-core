# New Tilt Generators - Anti Vibe-Coding Architecture

> **Mission**: Eliminate constant service failures by adding 7 new generators that enforce constraints at build time.

## The Problem

Services keep failing every month/day due to:
1. **Frontend builds failing** because TypeScript path aliases point to source files outside Docker context
2. **Database authentication errors** because credentials aren't validated before service startup
3. **Missing dependencies** causing Tilt warnings and runtime failures
4. **Environment variable mismatches** causing runtime crashes
5. **Package publishing gaps** where shared packages aren't published to Verdaccio

## The Solution: 7 New Generators

We've created **7 new Starlark generators** that act as "lithography machines" - they catch issues BEFORE services fail:

### 1. 🛡️ `validators.star` - Pre-Flight Validation Generator
**Purpose**: Run 7 validation checks before any service starts

**Checks**:
- Docker path alias validation (catches the CSS import failure)
- Dependency graph validation (catches missing lib-product-timezone-utils)
- Database readiness validation (catches auth failures)
- Package publishing validation (catches unpublished packages)
- Environment variable validation (catches missing env vars)
- Service health validation (catches missing required files)
- Shared package copy validation (ensures packages in Docker context)

**Usage**:
```starlark
# In manifest_resource.star, during config-gen:
load("../generators/index.star", "Generators")

# Run all validations
validation_report = Generators.run_pre_flight_validations(
    service_path,
    manifest,
    all_services,
    global_config,
)

# Check if service is safe to build
if validation_report["overall_status"] == "FAILED":
    print("⚠️ Service has validation failures - fix before building")
    # Validation reports written to autogenerated/validation-*.json
```

**Output Files**:
- `autogenerated/validation-master-report.json` - Summary of all validations
- `autogenerated/docker-path-validation.json` - Path alias issues
- `autogenerated/dependency-validation.json` - Missing dependencies
- `autogenerated/db-readiness-validation.json` - Database config issues
- `autogenerated/package-publish-validation.json` - Package publishing status
- `autogenerated/env-validation.json` - Environment variable issues
- `autogenerated/health-check.sh` - Pre-flight health check script
- `autogenerated/docker-shared-packages.json` - Packages to copy to Docker context

### 2. 📝 `fixed_frontend_tsconfig.star` - Docker-Safe TSConfig
**Purpose**: Fix the path alias issue that breaks frontend builds in Docker

**The Problem**:
```json
// OLD: tsconfig.docker.autogenerated.json
{
  "compilerOptions": {
    "paths": {
      "@/*": ["../src/*"],
      "@tdk/product-introvertic-ui": ["../../../../shared-product-engineering/product-introvertic-ui/src"],
      // ^ This breaks Docker build! Source files aren't in Docker context
    }
  }
}
```

**The Solution**:
```json
// NEW: Docker tsconfig (auto-generated)
{
  "compilerOptions": {
    "paths": {
      "@/*": ["../src/*"]
      // NO @tdk/* aliases - resolve from node_modules instead
    }
  }
}
```

**Usage**:
```starlark
load("../generators/index.star", "Generators")

# Generate Docker-safe tsconfig
config_path = Generators.generate_fixed_frontend_tsconfig(
    service_path,
    internal_deps,  # Still provided, but ignored in Docker builds
    is_docker=True,  # This is the key!
    write_file_if_changed,
)
```

**Key Insight**:
- Local builds: Use path aliases to source for faster development
- Docker builds: Resolve from node_modules (packages must be published)

### 3. 📦 `dependency_manifest.star` - Missing Dependency Resolver
**Purpose**: Generate manifests and stubs for missing dependencies like `lib-product-timezone-utils`

**Features**:
- Scans all package.json files for @TDK Landscape dependencies
- Identifies which dependencies don't exist as libraries
- Generates stub manifests for missing libraries
- Creates topology updates to add missing libs to config.star

**Known Missing Libraries Registry**:
```starlark
KNOWN_LIBRARY_REGISTRY = {
    "product-timezone-utils": {
        "type": "product",
        "path": "shared-product-engineering/product-timezone-utils",
        "description": "Timezone utilities for appointment scheduling",
    },
    # ... more known libraries
}
```

**Usage**:
```starlark
load("../generators/index.star", "Generators")

# Resolve all missing dependencies
report = Generators.resolve_missing_dependencies(
    all_services,
    library_roots,
)

# If missing deps found:
# 1. Creates stub library directories
# 2. Generates manifest.json files
# 3. Provides code to update discovery/config.star
```

**Output**:
- `dependency-resolution-report.json` - Full report of missing deps
- `generated-manifest-{lib_name}.json` - Manifest for each missing lib
- `topology-updates.json` - Code snippets for config.star

### 4. 🗄️ `database_provisioner.star` - Database Provisioning
**Purpose**: Ensure databases are properly provisioned before services start

**The Problem**: Current error:
```
Error: P1000: Authentication failed against database server
Please make sure to provide valid database credentials
```

**The Solution**: 
- Generate Docker Compose entries for per-service databases
- Create SQL scripts to provision users and grant privileges
- Validate database credentials before service startup
- Generate connection strings in proper format

**Usage**:
```starlark
load("../generators/index.star", "Generators")

# Provision database for a service
provisioning = Generators.provision_service_database(
    service_name="appointment-planner",
    db_name="TDK_planner",
    db_config=global_config.database,
    write_file_if_changed,
)

# Creates:
# - db-compose-entry.json
# - db-setup.sql
# - db-connection-strings.txt
# - db-provision.sh
```

**Generated Files**:
- `db-compose-entry.json` - Docker Compose configuration
- `db-setup.sql` - SQL to create database and user
- `db-connection-strings.txt` - DATABASE_URL values
- `db-provision.sh` - Script to provision database
- `db-credentials-validation.json` - Validation report

## Integration Guide

### Step 1: Update manifest_resource.star to Run Validations

**File**: `.tilt/topologies/tilt/resources/manifest_resource.star`

Add validation call in the config-gen resource:

```starlark
load("../generators/index.star", "Generators")

def create_config_resource(service_name, resource, service_path, manifest, backend_manifest, ctx):
    # ... existing code ...
    
    # NEW: Run pre-flight validations
    validation_report = Generators.run_pre_flight_validations(
        service_path,
        manifest,
        ctx.all_services,  # Need to pass all services
        ctx.global_config,
    )
    
    # If validation fails, print warnings but continue
    # (Let the user decide whether to proceed)
    if validation_report["overall_status"] == "FAILED":
        print("⚠️ {} has validation failures - check autogenerated/validation-*.json".format(
            service_name
        ))
    
    # ... rest of config generation ...
```

### Step 2: Use Fixed TSConfig Generator for Frontends

Replace the old frontend tsconfig generator:

```starlark
# OLD (in typescript/frontend_tsconfig.star)
def generate_frontend_tsconfig(..., is_docker=True):
    # Bug: Still includes path aliases when is_docker=True
    
# NEW (use fixed generator)
load("../generators/index.star", "Generators")

def generate_service_configs(service_path, manifest, ...):
    if manifest.appType == "frontend":
        # Use Docker-safe generator
        Generators.generate_fixed_frontend_tsconfig(
            service_path,
            internal_deps,
            is_docker=True,  # Always True for Docker builds
            write_file_if_changed,
        )
```

### Step 3: Run Dependency Resolution at Topology Load

**File**: `.tilt/topologies/tilt/discovery/loading.star`

```starlark
load("../generators/index.star", "Generators")

def initialize_discovery(cache):
    # ... existing discovery code ...
    
    # NEW: Resolve missing dependencies
    missing_deps_report = Generators.resolve_missing_dependencies(
        cache["app_services"],
        library_roots,
    )
    
    # Store in cache for later use
    cache["missing_dependencies"] = missing_deps_report
    
    # If missing deps found, warn but continue
    if missing_deps_report["status"] == "MISSING_DEPENDENCIES_FOUND":
        print("")
        print("⚠️ Missing Dependencies Found - Run 'bun run tilt:fix-deps' to generate stubs")
        print("")
```

### Step 4: Integrate Database Provisioning

**File**: `.tilt/topologies/platform/state/relational.star`

```starlark
load("../../tilt/generators/index.star", "Generators")

def provision_database(service_name, db_name, db_config):
    # Use the new provisioner
    provisioning = Generators.provision_service_database(
        service_name,
        db_name,
        db_config,
        write_file_if_changed,
    )
    
    # Return compose entry
    return provisioning.provisioning.compose_entry
```

## Immediate Fixes for Current Issues

### Fix 1: appointment-planner-frontend Build Failure

**Action**: Replace broken tsconfig generator with fixed version

```bash
# 1. Update the generator call in manifest_resource.star
# 2. Trigger rebuild
tilt trigger appointment-planner-frontend
```

**Verification**:
- Path aliases should NOT include @tdk/* in Docker tsconfig
- Build should resolve packages from node_modules

### Fix 2: appointment-planner-backend Database Auth

**Action**: Ensure database is provisioned with correct credentials

```bash
# 1. Check if database exists
docker exec TDK_postgres psql -U postgres -c "\l" | grep TDK_planner

# 2. If not, run provisioning script
# (Generated by database_provisioner.star)
tilt trigger provision-db-appointment

# 3. Restart backend
tilt trigger appointment-planner-backend
```

**Verification**:
- `TDK_planner` database should exist
- `TDK Landscape` user should have privileges

**Action**: Add to KNOWN_LIBRARY_REGISTRY and generate stub

```starlark
# Add to dependency_manifest.star:
KNOWN_LIBRARY_REGISTRY["product-timezone-utils"] = {
```
