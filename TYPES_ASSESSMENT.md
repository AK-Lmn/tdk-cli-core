## 2. Consolidation Opportunities

### 2.1 HIGH CONFIDENCE Consolidations

#### ✅ COMPLETED: FileWriteTask vs FileGenerationTask
**Issue:** Two interfaces for the same concept - file generation tasks.

| | `FileGenerationTask` (types/index.ts) | `FileWriteTask` (file-helpers.ts) |
|---|---|---|
| `type` | `ResourceFileType` ('json' \| 'text') | `'json' \| 'text'` |
| `filename` | `string` | `string` |
| `content` | `JsonValue` | `unknown` ⚠️ Weaker type |
| `description` | `string` | `string` |
| `emoji` | `string` | `string` |

**Resolution:** 
- Kept `FileGenerationTask` in types/index.ts as the canonical type
- Updated `file-helpers.ts` to use `FileGenerationTask` instead of `FileWriteTask`
- Removed duplicate `FileWriteTask` interface
- Updated imports in `resource.ts` that used the local type import

**Files Modified:**
- `cli/src/utils/file-helpers.ts` - Removed FileWriteTask, now uses FileGenerationTask
- `cli/src/commands/resource.ts` - Updated import to use FileGenerationTask from types

### 2.2 MEDIUM CONFIDENCE Consolidations

#### Status Type Unification (Analysis Only - Not Implemented)
**Observation:** Multiple status types exist but serve different semantic purposes:

| Type | Values | Usage |
|------|--------|-------|
| `ResourceStatus` | 'ready' \| 'pending' \| 'error' \| 'unknown' | Resource health |
| `StackHealthStatus` | 'healthy' \| 'degraded' \| 'error' \| 'unknown' | Stack aggregate health |
| `TiltRuntimeStatus` | 'running' \| 'pending' \| 'error' \| 'unknown' | Tilt process state |
| `ServiceUrl['status']` | 'running' \| 'stopped' \| 'unknown' | URL accessibility |
| `StatusValue` | Comprehensive union | General status display |

**Decision:** Kept separate. These types represent different domain concepts (health vs runtime vs accessibility). The `StatusValue` type already serves as the display-level unification.

## 5. Architecture Assessment

### Strengths
1. **Strong central types file** - 45 well-organized type definitions
2. **Explicit exports/imports** - No wildcard exports, all type imports use `type` keyword
3. **Domain-driven naming** - Types follow resource/stack/project domain boundaries
4. **Proper type guards** - `isCreatableResourceType()` for runtime validation
5. **Recursive JSON types** - Proper `JsonValue` with circular references handled

### Recommendations
1. Consider organizing `types/index.ts` into smaller domain-specific modules if it grows beyond 60 definitions
2. The `StatusValue` type is quite large (15+ variants) - consider if all variants are actively used
3. `TooltipProps` is an alias of `BaseTooltipProps` - consider if both are needed or if components should use `BaseTooltipProps` directly
