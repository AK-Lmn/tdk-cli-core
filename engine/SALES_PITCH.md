## The Problem: Why Infrastructure Autogeneration Fails

### The AI Infrastructure Trap

AI writes code like this:

```yaml
# Service 1 (AI-generated)
ports:
  - "3000:3000"

# Service 2 (AI-generated)
ports:
  - "3000:3000"  # CONFLICT!
```

**AI has zero context:** It doesn't know about existing services, used ports, or dependency graphs. Every AI-generated service creates technical debt.

## The Solution: Level 3 Autogeneration

### How It Works

```
service.json ──▶ VALIDATE ──▶ RESOLVE ──▶ GENERATE ──▶ VERIFY ──▶ ATOMIC WRITE
                  ↑            ↑            ↑           ↑
                  └────────────┴────────────┴───────────┘
                           Context Object
                    (all services, ports, deps)
```

**Step 1: Validate**  
Check manifest structure. Catch missing fields early.

**Step 2: Resolve**  
```python
def resolve_port(manifest, ctx):
    if manifest['port'] in ctx.port_allocations:
        return find_next_available(ctx.port_allocations)
    return manifest['port']
```
Zero port conflicts.

**Step 3: Generate**  
Starlark code with full context:
```python
def generate_for_manifest(manifest, ctx):
    return {
        'docker': generate_docker(manifest, ctx),
        'nginx': generate_routing(manifest, ctx.topology),
        'vite': generate_build(manifest, ctx.toolchain)
    }
```

**Step 4: Verify**  
Syntax check + semantic validation. No broken configs.

**Step 5: Atomic Write**  
All configs update together. Never partial state.

### What Gets Generated

From one `service.json`:
```json
{
  "name": "payment-service",
  "port": 3005,
  "dependencies": ["postgres", "redis"]
}
```

Platform creates:
- `docker-compose.payment-service.autogenerated.yml`
- `nginx.payment-service.autogenerated.conf`
- `vite.config.payment-service.autogenerated.ts`
- `.env.payment-service.autogenerated`

All validated. All consistent. All working.

## Technical Deep Dive

### The Context Object

```python
type Context struct {
    all_services: []       # Every manifest
    port_allocations: {}   # Map of service → port
    dependency_graph: {}   # Full DAG
    network_topology: {}   # Service connections
    secrets: {}            # Environment vars
    toolchain_versions: {} # Bun, Node versions
}
```

Generators don't work in isolation. They see the entire system.

### Dependency Resolution

```python
def resolve_deps(manifest, ctx):
    deps = manifest.get('dependencies', [])
    
    # Verify existence
    for dep in deps:
        if dep not in ctx.all_resource_names:
            raise ConfigError(f"Unknown: {dep}")
    
    # Detect cycles
    if has_cycle(deps, ctx.dependency_graph):
        raise ConfigError("Circular dependency")
    
    # Return topological order
    return topological_sort(deps, ctx.dependency_graph)
```

Dependencies always resolve. Cycles caught early.

### Auto-Discovery

```python
def discover_services(root):
    services = []
    for path in walk(root):
        if exists(join(path, 'service.json')):
            services.append({
                'path': path,
                'manifest': load_json(join(path, 'service.json'))
            })
    return services
```

Drop a `service.json` anywhere. Platform finds it.
