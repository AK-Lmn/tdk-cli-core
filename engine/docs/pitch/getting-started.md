# Getting Started

## 30-Second Quick Start

### 1. Install

```bash
git clone https://github.com/your-org/manifest-driven-platform
cd manifest-driven-platform
./install.sh
```

### 2. Create Your First Service

```bash
mkdir services/my-api
cat > services/my-api/service.json << 'EOF'
{
  "name": "my-api",
  "port": 3000,
  "type": "api",
  "dependencies": []
}
EOF
```

### 3. Run

```bash
tilt up
```

**Done!** The platform generates:
- `docker-compose.my-api.autogenerated.yml`
- `nginx.my-api.autogenerated.conf`
- `vite.config.my-api.autogenerated.ts`
- `.env.my-api.autogenerated`

**Time:** 30 seconds. **Fixes needed:** 0.

## Step-by-Step Tutorial

### Prerequisites

- Docker installed
- Tilt installed (`brew install tilt` or see [tilt.dev](https://tilt.dev))
- Basic understanding of JSON

### Step 1: Project Setup

Create a new project directory:

```bash
mkdir my-project
cd my-project
git init
```

Create a `Tiltfile`:

```starlark
# Load the manifest-driven platform
load('ext://manifest-driven', 'manifest_resource')

# Auto-discover and register all services
manifest_resource.auto_discover('./services')
```

### Step 2: Create a Service

Create the services directory:

```bash
mkdir -p services/user-api
```

Create `services/user-api/service.json`:

```json
{
  "name": "user-api",
  "port": 3001,
  "type": "api",
  "dependencies": ["postgres"],
  "routes": ["/api/users/*"],
  "environment": {
    "DATABASE_URL": "postgresql://localhost:5432/users"
  }
}
```

### Step 3: Add Code

Create `services/user-api/src/index.js`:

```javascript
const express = require('express');
const app = express();

app.get('/api/users', (req, res) => {
  res.json({ users: [] });
});

const port = process.env.PORT || 3001;
app.listen(port, () => {
  console.log(`User API running on port ${port}`);
});
```

Create `services/user-api/package.json`:

```json
{
  "name": "user-api",
  "version": "1.0.0",
  "scripts": {
    "start": "node src/index.js",
    "dev": "nodemon src/index.js"
  },
  "dependencies": {
    "express": "^4.18.0"
  },
  "devDependencies": {
    "nodemon": "^3.0.0"
  }
}
```

### Step 4: Run Tilt

```bash
tilt up
```

You'll see:
1. Platform discovers `user-api/service.json`
2. Generates all config files
3. Builds Docker image
4. Starts the service
5. Sets up hot reload

### Step 5: Verify

Check generated configs:

```bash
ls autogenerated/
# docker-compose.user-api.autogenerated.yml
# nginx.user-api.autogenerated.conf
# vite.config.user-api.autogenerated.ts
# .env.user-api.autogenerated
```

View the service:

```bash
curl http://localhost:3001/api/users
# {"users": []}
```

### Step 6: Add Another Service

Create `services/order-api/service.json`:

```json
{
  "name": "order-api",
  "port": 3002,
  "type": "api",
  "dependencies": ["postgres", "user-api"],
  "routes": ["/api/orders/*"]
}
```

Add code, then run:

```bash
# Tilt auto-detects the new service
# Generates configs automatically
# Starts the service
```

Notice:
- Port 3002 auto-assigned (no conflict with 3001)
- Dependencies auto-resolved (waits for postgres and user-api)
- Zero manual config editing

### Step 7: Hot Reload Test

Edit `services/user-api/service.json`:

```json
{
  "name": "user-api",
  "port": 3005,  // Changed from 3001
  "type": "api",
  "dependencies": ["postgres"],
  "routes": ["/api/users/*", "/api/profiles/*"]  // Added route
}
```

**What happens:**
1. Platform detects change
2. Regenerates all configs
3. Updates Docker Compose
4. Updates Nginx routing
5. Restarts service with new port
6. **No manual fixes needed**

## Common Workflows

### Adding a New Service

```bash
# 1. Create directory
mkdir services/new-service

# 2. Create manifest
cat > services/new-service/service.json << 'EOF'
{
  "name": "new-service",
  "port": 0,
  "type": "api"
}
EOF

# 3. Add code
echo "console.log('Hello')" > services/new-service/index.js

# 4. Platform auto-detects and generates configs
# (If tilt is already running, just wait 5 seconds)
```

### Updating a Service

```bash
# 1. Edit service.json
vim services/my-api/service.json

# 2. Platform auto-regenerates configs
# 3. Hot reload applies changes
```

### Removing a Service

```bash
# 1. Remove directory
rm -rf services/old-service

# 2. Platform auto-detects removal
# 3. Cleans up generated configs
```

### Viewing Generated Configs

```bash
# All configs
cat autogenerated/docker-compose.my-api.autogenerated.yml

# Specific config
cat autogenerated/nginx.my-api.autogenerated.conf
```

### Debugging

```bash
# Check Tilt status
tilt status

# View logs
tilt logs

# Trigger manual regeneration
tilt trigger my-api-config-gen

# Full restart
tilt down && tilt up
```

## Service Types

### API Service

```json
{
  "name": "my-api",
  "port": 3000,
  "type": "api",
  "dependencies": ["postgres", "redis"],
  "routes": ["/api/v1/*"],
  "replicas": 2
}
```

**Generates:**
- Docker Compose with load balancing
- Nginx upstream configuration
- Health check endpoints
- Auto-scaling rules

### Web Service

```json
{
  "name": "my-frontend",
  "port": 3001,
  "type": "web",
  "dependencies": ["my-api"],
  "backend_name": "my-api"
}
```

**Generates:**
- Vite development config
- Nginx SPA routing
- API proxy configuration
- Hot reload setup

### Worker Service

```json
{
  "name": "my-worker",
  "port": 0,
  "type": "worker",
  "dependencies": ["redis", "postgres"],
  "queue": "default"
}
```

**Generates:**
- Background job configuration
- Queue consumer setup
- No external port (internal only)

### Library

```json
{
  "name": "my-library",
  "type": "library",
  "publish_to": "verdaccio"
}
```

**Generates:**
- TypeScript build config
- Package publishing setup
- Dependency linking

## Environment Variables

### Automatic Variables

The platform automatically sets:

```bash
# Service identification
SERVICE_NAME=user-api
SERVICE_PORT=3001
SERVICE_TYPE=api

# Database (if dependency declared)
DATABASE_URL=postgresql://user-api-db:5432/user_api

# Redis (if dependency declared)
REDIS_URL=redis://redis:6379

# Internal networking
INTERNAL_HOST=user-api
INTERNAL_PORT=3001

# Dependencies (comma-separated)
DEPENDS_ON=postgres,redis
```

### Custom Variables

Add to `service.json`:

```json
{
  "name": "my-api",
  "environment": {
    "API_KEY": "${API_KEY}",
    "DEBUG": "true",
    "LOG_LEVEL": "info"
  }
}
```

### Secret Variables

For secrets, use references:

```json
{
  "name": "my-api",
  "environment": {
    "DATABASE_PASSWORD": "${secrets:db_password}"
  }
}
```

Actual values loaded from:
- `.env.local` (gitignored)
- Infisical/1Password (production)

## Troubleshooting

### "Port already in use"

**Cause:** Manual port conflict  
**Fix:** Use `"port": 0` for auto-assignment, or check `autogenerated/` for assigned ports

### "Dependency not found"

**Cause:** Referenced service doesn't exist  
**Fix:** Check `dependencies` array in `service.json`

### "Config not regenerating"

**Cause:** Tilt not watching file  
**Fix:** Run `tilt trigger <service-name>-config-gen`

### "Service won't start"

**Cause:** Various  
**Debug:**
```bash
# Check logs
tilt logs <service-name>

# Verify generated config
cat autogenerated/docker-compose.<service>.yml

# Manual test
docker-compose -f autogenerated/docker-compose.<service>.yml up
```
