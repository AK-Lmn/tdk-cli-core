## The problem AI won't solve

```yaml

  - "3000:3000"

# Service 2 (AI-generated)

  - "3000:3000"  # ❌ CONFLICT!
```

AI has zero context. It doesn't know:
- What ports are already taken
- Which services depend on which

## The solution we built

Level 7 manifest-driven autogeneration. One `service.json` file triggers 10+ generated configurations, all context-aware:

```json
{
  "appName": "payment-processor",
  "appType": "backend",
  "domain": "finance",
  "port": 4005,
  "databaseName": "payments_db",
  "features": ["nats", "prisma", "traefik"],
  "internalDependencies": ["identity", "platform-eventing"]
}
```

This single manifest generates:
- Validated port allocation (no conflicts)
- Dependency graph resolution
- Docker Compose configuration
- TypeScript/Vite configs with correct paths
- Traefik routing rules
- Database provisioning
- Environment variable injection

Change one file, everything updates. No manual edits to 10 config files.

## The 5-step validation pipeline

Every manifest passes through:

1. **Discovery:** Auto-detect new `service.json` files (5-second polling)
2. **Validation:** JSON schema + custom rules (port ranges, dependency existence)
3. **Synthesis:** Build complete context object (dependencies, routing, database)
4. **Generation:** Starlark-based config generation (not templates)
5. **Orchestration:** Tilt resources with proper dependency chains

Failure at any step = immediate feedback, no broken configs committed.
