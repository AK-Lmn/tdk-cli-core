Frequently Asked Questions

❓ But we need Kubernetes for production anyway

Local dev doesn't need to match production. Different concerns. Use TDK for fast local iteration, K8s for prod when you're ready. Decoupled.

❓ What about CI/CD?

TDK is completely decoupled from your CI. Use it for local development, whatever you want for CI/CD. No lock-in. No migration headache.

❓ Our platform team already set up Garden

TDK complements Garden. Use TDK for local speed (5s startup vs 30s), Garden for prod-like integration tests. Best of both worlds.

❓ Is 120+ services actually realistic locally?

Yes. With selective startup and resource management. We've proven this scales in production. You don't run all 120 at once—you run what you need.

❓ What if we outgrow TDK?

TDK uses standard Docker + Tilt. No proprietary formats. Easy migration path to any other tool if you ever need to.

❓ Who is TDK for?

Full-stack developers, product teams, and startups who want to run microservices locally without becoming DevOps engineers.
