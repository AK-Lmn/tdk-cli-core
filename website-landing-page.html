How TDK works

One manifest file. Multiple configurations generated automatically.

1

Write service.json

Simple JSON manifest with app name, type, port, and features. The single source of truth.

2

TDK generates configs

Dockerfile, Vite config, TypeScript, nginx, environment files, and more—automatically.

3

Tilt orchestrates

Built on Tilt (9.4k GitHub stars). Runs your services locally in Docker containers with hot reload.

4

You write code

No Kubernetes knowledge needed. No complex YAML. Just focus on building your product.

Common questions

Quick answers to frequent concerns.

But we need Kubernetes for production

Local dev doesn't need to match production. Use TDK for fast local iteration (5s startup), K8s for prod when ready. Decoupled, no lock-in.

What about CI/CD?

TDK is completely decoupled from your CI. Use it for local development, whatever you want for CI/CD. No migration headache if you switch.

We already use Garden

TDK complements Garden. Use TDK for local speed (5s vs 30s startup), Garden for prod-like integration tests. Best of both.

Is 120+ services realistic locally?

Yes, with selective startup. You don't run all 120 at once—you run what you need. Proven at scale with proper resource management.

What if we outgrow TDK?

TDK uses standard Docker + Tilt. No proprietary formats. Easy migration to any other tool if you ever need to.

Who is TDK for?

Full-stack developers, product teams, and startups who want to run microservices locally without becoming DevOps engineers.

Who should use what

Choose the right tool for your team's expertise.

Platform Engineers

Use Garden or DevSpace. They WANT Kubernetes and have the expertise to manage it.

Senior Backend Devs

Use Tilt or Skaffold. They tolerate K8s complexity and can handle the learning curve.

Full-Stack Developers

Use TDK. Don't know K8s, don't want to learn it. Just want to write code and ship features.

Product Teams

Use TDK. Need to test features across 10+ services without waiting for DevOps.

Startups

Use TDK. Outgrew "works on my machine" but not ready for platform engineering overhead.
