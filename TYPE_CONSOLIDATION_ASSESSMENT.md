# Type System Consolidation Assessment

## Executive Summary

The TDK CLI codebase has a **well-organized type system** with most shared types already centralized in `cli/src/types/index.ts`. The types follow consistent naming conventions and are properly exported. However, there are opportunities for consolidation and a few inconsistencies that should be addressed.

**Overall Health: 8/10** - Good organization with minor consolidation opportunities.

## 5. Consolidation Recommendations

### 🔴 High Priority (Implement Now)

#### 1. Fix `VALID_RESOURCE_TYPES` Array (Type Safety Issue)

**Problem:** The `VALID_RESOURCE_TYPES` array in `constants.ts` is missing values from `ResourceType`:
- Array: `['backend', 'frontend', 'worker']`
- Type: `'backend' | 'frontend' | 'library' | 'sdk' | 'worker' | 'migrator'`

**Impact:** Runtime validation doesn't match compile-time types, may reject valid resource types.

**Fix:** Update `constants.ts` to include all valid types.

**Risk:** Low - Adding values to validation is backwards compatible.

---

### 🟡 Medium Priority (Consider)

#### 2. Strengthen `ResourceType` Inference in `services.ts`

**Current:**
```typescript
let type: ResourceType = 'backend';
if (resource.name.includes('frontend')) {
  type = 'frontend';
} else if (resource.name.includes('sdk') || resource.name.includes('lib') || resource.name.includes('infra')) {
  type = 'library';
}
```

**Issue:** Missing `worker` and `migrator` inference, heuristic-based typing is weak.

**Fix:** Use `config.appType` from `ResourceConfig` which already contains the type.

**Risk:** Low - Uses already-validated data from config.

---

### 🟢 Low Priority (Nice to Have)

#### 3. Add Type Predicates Where Missing

Currently using inline type guards. Could extract reusable predicates:
- `isNodeError` in `services.ts` - already follows good pattern
- `isValidResourceConfig` - already exists

**Recommendation:** Keep as-is. Current pattern is clear and local.
