## 2. Findings & Recommendations

### 2.1 ✅ Strengths

1. **Centralized Type Definitions**: 45+ types properly centralized in `types/index.ts`
2. **Consistent Naming**: All types use PascalCase correctly (interfaces, type aliases)
3. **Discriminated Unions**: Excellent use for `StatusValue`, `StatusCategory`, `TabId`
4. **Type Safety**: Strict TypeScript configuration with explicit return types
5. **Runtime Validation**: Type guards present for critical validation paths
6. **Const Assertions**: Good use of `as const` for configuration objects
7. **Extract Types**: Smart use of `Extract<>` for type subsets

### 2.2 ⚠️ Areas for Improvement

#### Priority 1: Consolidate Component Props

**Issue**: `FileTreeProps` defined locally in `FileTree.tsx` while other component props are in `types/index.ts`.

**Recommendation**: Move `FileTreeProps` to `types/index.ts` for consistency.

#### Priority 2: Extract Inline Types

**Issue**: Several inline types in `ui.tsx`:
```typescript
const LoadingScreen: React.FC<{ progress: number; message: string }>
const ErrorScreen: React.FC<{ error: string; onRetry: () => void }>
const HelpPanel: React.FC<{ onClose: () => void }>
```

**Recommendation**: Extract to named interfaces in `types/index.ts`.

#### Priority 3: Unused TooltipProps Properties

**Issue**: `TooltipProps` has properties not used by the simple Tooltip component:
- `wrapText` (always true in Tooltip)
- `prefix` (not used)
- `marginTop` (not used)

**Recommendation**: Create separate `BaseTooltipProps` and `TooltipProps` types.

#### Priority 4: Duplicate Type Definition

**Issue**: `Job` interface defined inline in `resource.ts` (lines 229-235) as template string, not actual TypeScript type.

**Status**: This is actually a template string, not a duplicate type - **No action needed**.

#### Priority 5: Missing Type for Template Constants

**Issue**: Template constants like `BASE_TEMPLATE`, `TYPE_SPECIFIC`, `TSCONFIG_TEMPLATE` could benefit from stronger typing.

**Recommendation**: Consider extracting to proper type definitions if they grow in complexity.

## 3. Inconsistencies Identified

### 3.1 Naming Convention Inconsistency

**Status**: ✅ **All naming follows AGENTS.md conventions**
- Interfaces: PascalCase without redundant suffixes
- Type aliases: PascalCase
- Boolean properties: `is-*`, `has-*`, `can-*`, `did-*` prefixes

### 3.2 Import Pattern Inconsistency

**Issue**: Minor inconsistency in type imports:

```typescript
// Some files use:
import type { X } from '../types/index.js';

// Others use (incorrect):
import { X } from '../types/index.js';
```

**Recommendation**: Standardize on `import type` for type-only imports.

### 3.3 Export Pattern

**Status**: ✅ **Follows AGENTS.md guidelines**
- Explicit named exports from `types/index.ts`
- No wildcard exports
- Type exports grouped with `export type`

## 4. Recommendations Summary

### High Confidence (Implement Immediately)

1. **Move FileTreeProps to types/index.ts**
   - Low risk, improves consistency
   - Single file change

2. **Extract UI component props from ui.tsx**
   - `LoadingScreenProps`
   - `ErrorScreenProps`  
   - `HelpPanelProps`
   - Improves reusability and testing

3. **Split TooltipProps into BaseTooltipProps and TooltipProps**
   - Clarifies which props are used where
   - Prevents confusion about available options

### Medium Confidence (Consider for Future)

4. **Standardize all type imports to use `import type`**
   - Improves build performance
   - Better clarity about type-only dependencies

5. **Add runtime validation schemas**
   - Consider Zod for service.json validation
   - Replace manual type guards with generated validators

### Low Priority (Optional)

6. **Consider branded types for identifiers**
   - `type ResourceName = string & { __brand: 'ResourceName' }`
   - Prevents accidental mixing of different string types
