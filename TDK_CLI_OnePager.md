**Kubernetes-Free Microservice Development**

Run 5-120+ microservices locally without learning Kubernetes. No clusters. No YAML hell. Just Docker and Tilt.

---

## How It Works

**1. Write service.json**
```json
{
  "appName": "order-frontend",
  "appType": "frontend",
  "port": 3001,
  "features": ["vite", "typescript"],
  "backendName": "order-backend"
}
```

**2. TDK generates configs automatically**
- `Dockerfile.frontend.autogenerated`
- `vite.config.frontend.autogenerated.ts`
- `tsconfig.frontend.autogenerated.json`
- `nginx.frontend.autogenerated.conf`
- `.env.frontend.autogenerated`
- ...and 5 more files

**3. Tilt orchestrates locally**
Built on Tilt (9.4k GitHub stars). Hot reload. Selective startup. Docker only.

**4. You write code**
No Kubernetes knowledge required. No complex YAML. Just focus on your product.

## Common Objections

**"But we need Kubernetes for production anyway"**
→ Local dev doesn't need to match production. Use TDK for fast local iteration (5s startup), K8s for prod when ready. Decoupled.

**"What about CI/CD?"**
→ TDK is completely decoupled. Use it for local development, whatever you want for CI. No lock-in.

**"We already use Garden"**
→ TDK complements Garden. Use TDK for local speed, Garden for prod-like integration tests.

**"Is 120+ services realistic locally?"**
→ Yes, with selective startup. You don't run all 120 at once—just what you need. Proven at scale.

**"What if we outgrow TDK?"**
→ TDK uses standard Docker + Tilt. No proprietary formats. Easy migration path.

## Technical Details

**Golden Image Layering**
```
L1: Base OS (Alpine/Ubuntu)
L2: Runtime (Bun/Node)
L3: App dependencies
L4: Service code
```

**Architecture**
```
service.json (single source of truth)
    ↓
Generator Engine (Starlark)
    ↓
Tilt orchestrates Docker containers
```

**Proven Scale**
- 120+ services running locally
- 10+ config files per service
- 70% reduction in "works on my machine" issues
